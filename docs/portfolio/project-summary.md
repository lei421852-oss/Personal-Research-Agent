# 项目介绍与面试讲解

## 简历精简版

**Multimodal Research Agent｜证据驱动的论文研究智能体**

- 构建基于 ReAct 工具循环的主 Agent，将本地论文发现、查询扩展、证据检索和多 Agent 研究统一为按需动作；以单动作校验、共享预算和有界协议纠正约束执行。
- 实现 Planner / 逐论文 Worker / Reviewer / Recovery / Synthesis 协作链，通过证据身份、引用白名单和审核准入构建可追溯报告，保留拒绝、缺失、失败及降级状态。
- 开发中文研究工作台，按真实增量事件自动切换线性轨迹与论文分工协作树，优先展示直接答案，支持引用详情、取消及只读历史回放。

技术：Python、FastAPI、Pydantic、asyncio、PyTorch / Transformers、Qwen Embedding、Chroma、OpenAI-compatible API、原生前端、pytest / Playwright。

不写“人审准确率 87.78%”“全面像素级视觉理解”“所有复杂题自动成功”。当前是受控论文语料工程原型；量化测试与样本指标须同时给出来源、时间及分母。

## 三个技术亮点

1. **自主决策与确定性约束分离**：模型判断是否继续研究，程序不按关键词填论文范围，也不截取多动作中的第一个。违规批次不执行，反馈后由模型重新选择。
2. **研究事实的审核准入**：单论文调查、引用结构验证和语义 Reviewer 分工；只有获准 Claim 进入 Synthesis，恢复最多一轮且必须再次审核。生成成功与证据覆盖率分开。
3. **可观察的协作工作台**：图形依据后端实际事件，缺失角色不补画；各论文 Worker 与审核归属可查看。树是职责图，不伪造并行时间线。

## 面试问答

**为什么需要主 Agent？** 固定 RAG 无法表达何时补页、读图、发现论文或启动更深调查。主 Agent 让这些步骤由当前问题与观察决定，同时保留程序安全边界。

**为什么不默认运行多 Agent？** 简单问题可能两次检索就足够。额外规划、Worker、审核和综合增加延迟、调用数及协议失败机会，深度收益需要实验而非默认假设。

**如何控制预算？** 主 Agent 最多 6 个工具、7 次决策；策略纠正共享决策预算。全请求物理调用账本覆盖主决策、翻译、扩展、子链、重试和 VLM；研究工具最多启动一次，子链不获得新额度。

**模型返回多个动作怎么办？** 全部拒绝、不执行工具，发送结构化数量与格式反馈，默认最多 2 次纠正。真实 BLIP-2/Flamingo 示例已保存一次多动作 → 模型修正；耗尽仍是明确失败，不强制 finish。

**候选论文与研究证据有什么不同？** Paper Index 的 25 篇元数据用于发现；当前只有 5 篇准备了正文 / Figure 片段。标题、摘要和画像不能直接冒充本次正文引用。

**如何避免引用幻觉？** 程序检查 Evidence ID 的存在、当前 Corpus、归属与观察白名单；研究 Claim 还要经过 Reviewer。它能阻止虚构身份，却不能完全证明自然语言语义正确。

**何时判定证据不足？** Policy 根据需求与已观察材料提交明确不足；未准备正文 / 页面是客观边界。Provider 故障和 execution_failed 不自动解释成合理拒答。

**当前局限有哪些？** 固定人工 Prepared Corpus、本地发现、有限工具、有限预算、单进程历史；没有自动 PDF 解析、外部实时搜索或完整人审 Benchmark。VLM 可选路径不等于当前比较评测验证了像素推理。

## 如何引用实验

F2 的 79/90 是 AI 辅助参考评分结果，人工 Gold 为 0；F3.1-E 的 4/7 来自已知失败诊断集，不能外推泛化；G2.1 的 14/14 是合法终态，含 10 项证据不足，不是研究正确率。详见[实验汇总](../reports/experiment-summary.md)。

两个真实主 Agent 示例、Scripted 协作工具验证和 G2/G2.1 真实默认研究链回放各有不同证据。尚无可核验的真实主 Agent 自主协作产物时，明确说“待手动验收”，不凭 UI 截图声称完成了该模型实验。
