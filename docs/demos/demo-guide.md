# 演示操作指南

按[Quickstart](../guides/quickstart.md)启动中文工作台。左侧只需输入问题，论文目录是只读资源，不要求用户选择研究对象。

## 3–5 分钟展示顺序

1. 先展示[Demo A](demo-cases.md)：让观众理解主 Agent 可以及时结束，不默认运行多 Agent。
2. 展示[Demo B](demo-cases.md)：两个 scoped 文本工具仍是单 Agent；解释实际多动作拒绝及恢复记录。
3. 展示顶部 G2/G2.1 历史回放：明确告知“历史真实研究，当前不调用模型”，展开协作树与论文分支，点击 Worker / Reviewer 查看事实、缺口和错误。
4. 展示答案优先布局、可展开的详细报告、页码引用与限制。最后说明主模型新措辞及中文翻译没有自动继承独立审核。

上述 A/B 的已有真实 JSON 可以直接审阅，不要求现场重新付费调用。它们没有注册为新的回放按钮，不能声称 UI 已提供三案例回放。

## 现场复杂任务

如希望现场验证主 ReAct 自主协作，使用 Demo C 的完整问题。模型是否调用研究工具以真实事件为准；协作树只有实际调用后出现。缺失、审核拒绝、执行失败及降级报告原样保留，不能编辑展示文字掩盖失败。

本发布阶段不自动运行该任务。未经保存的主 Agent 协作产物状态为“待用户手动验收”，不是“真实验证通过”。

## 截图与运行环境

![模拟协作树](assets/scripted-collaboration-tree.png)

这张截图来自 Scripted/Fake Provider 的领域链和真实浏览器，只用于布局展示。树按实际角色与论文归属组织，连线不表示所有分支同时执行。手机窄屏折成单列，节点点击仍可查看记录。

离线复现截图对应的工程检查：

```bash
python -m scripts.check_react_workbench_ui \
  --output-dir artifacts/react-workbench-ui-check
```

需 Playwright / Chromium，可选 `--font-file`。输出目录是运行产物，默认不提交。完整原执行记录和受保护历史文件不改写。

## 演示故障处理

- UI 变化强制刷新；后端代码变化重启服务。重启会丢失尚未导出的进程内任务。
- Provider / 索引未就绪仍可回放；不要改模型或临时扩充语料来制造成功。
- 语言转换失败保留原文；取消等待在途同步请求收尾。
- `completed` 表示流程结束，核对 `answer_status`、VerifiedClaim、缺失矩阵和审核结果后再解释研究完成程度。
